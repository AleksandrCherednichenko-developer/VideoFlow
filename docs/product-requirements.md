# VideoFlow Product Requirements

**Версия:** 3.0

**Дата baseline:** 14 августа 2026

**Источник:** утверждённое [ТЗ DiPost v1.0](source/TZ_v1.0.md) от 25 июля 2026

## 1. Принятое отклонение

Первая реализация продукта создаётся как responsive PWA для iPhone и iPad вместо
native iOS-приложения. Все продуктовые сценарии исходного ТЗ сохраняются.

Следствия решения:

- APNs заменяется Web Push для установленной PWA;
- безопасная refresh-cookie сессия заменяет Keychain для сессии VideoFlow;
- токены социальных платформ остаются только на backend и шифруются;
- Photos и Files доступны через browser file picker; Camera используется через
  возможности iOS Safari;
- offline-сценарии реализуются через Service Worker и IndexedDB.

## 2. Цель и пользователь

Продукт сокращает подготовку одного мульти-поста до 2–4 минут. Основной
пользователь — solo-креатор UJC Creator во Вьетнаме, публикующий по timezone
`Europe/Moscow` с iPhone или iPad. Ожидаемая нагрузка — 80–120 видео в месяц.

## 3. Платформы

| Этап | Платформы |
|---|---|
| MVP | Instagram Reels, TikTok, YouTube Shorts |
| Этап 2 | VK Clips, Pinterest Video Pin |

На каждую платформу подключается ровно один аккаунт. Threads не входит в текущую
версию.

## 4. MVP

- email/password и Sign in with Apple;
- OAuth-подключение P0-платформ, статус токена и reconnect;
- выбор видео из Photos, Files или Camera;
- строгая проверка 9:16 и длительности до 60 секунд;
- preview и отдельные платформенные обложки;
- черновики без обязательного времени публикации;
- отдельные описания и копирование текста между платформами;
- планирование в `Europe/Moscow`;
- очередь и недельный календарь с drag-and-drop;
- редактирование, перенос и отмена до начала публикации;
- server-side публикация через официальные API;
- до трёх автоматических retry для временных ошибок;
- Web Push об успехе, ошибке и необходимости reconnect;
- история, ссылки, просмотры, лайки и сохранения;
- обновление метрик 2–4 раза в сутки;
- автоматическое удаление видео через 7 дней после публикации.

## 5. Нефункциональные требования

- успешность технически допустимых публикаций не ниже 97%;
- подтверждение планирования не дольше 15 секунд без учёта upload;
- HTTPS вне локальной разработки;
- server-side encryption социальных токенов;
- русский интерфейс, light/dark themes;
- стабильная работа на iPhone 12+ и актуальных iPad;
- offline-доступ к черновикам и последнему календарю.

## 6. Не входит

- native iOS-клиент в первой реализации;
- Android;
- web-продукт для desktop как отдельное направление;
- SaaS, workspaces, команды, роли, тарифы и billing;
- долгосрочная медиатека;
- AI-генерация, шаблоны, recurring posts;
- редактор видео, субтитры и водяные знаки;
- Threads.

## 7. Приёмка

MVP принимается по десяти критериям раздела 8 исходного ТЗ с адаптацией канала
уведомлений: вместо APNs используется Web Push установленной PWA. Каждая
платформенная интеграция проходит реальный end-to-end publish через официальный
API; наличие интерфейса или OAuth без публикации не закрывает критерий.
