## 1. Введение

### 1.1. Назначение документа
Настоящее Техническое Задание определяет полный набор требований к разработке мобильного приложения **DiPost** — инструмента для автоматической публикации коротких вертикальных видео товаров для животных в несколько социальных сетей по заранее заданному расписанию.

### 1.2. Цель проекта
Сократить время, которое креатор тратит на ручную публикацию одного видео во все соцсети, с 15–25 минут до 2–4 минут.  
Создатель загружает видео **один раз**, заполняет разные описания + артикулы, ставит время — и приложение само публикует контент даже когда телефон выключен.

### 1.3. Целевая аудитория
- Solo-креатор UJC Creator
- Устройства: iPhone + iPad
- География: живёт во Вьетнаме, публикует по московскому времени
- Объём контента: 80–120 видео в месяц

### 1.4. Платформа
Только **iOS** (iPhone и iPad).  
Минимальная версия: iOS 16.0+  
Веб-версия и Android **не требуются**.

## 2. Глоссарий

| Термин | Определение |
|--------|-------------|
| **Мульти-пост** | Одна загрузка видео + публикация в несколько выбранных платформ с индивидуальными описаниями |
| **Артикул** | Код товара (пример: #WW1233455), который пользователь вставляет в описание |
| **Очередь** | Список видео, ожидающих публикации в разное время |
| **Черновик** | Загруженное видео без назначенного времени публикации |
| **Токен** | OAuth access token социальной сети |

## 4. Пользовательские сценарии (User Stories)

**US-01. Создание мульти-поста**  
Как креатор, я хочу загрузить одно вертикальное видео 9:16, выбрать нужные соцсети, вставить разные описания с артикулами и назначить время публикации, чтобы видео автоматически ушло во все выбранные платформы.

**US-02. Очередь**  
Как креатор, я хочу загрузить сразу несколько видео и распределить их по разным временным слотам.

**US-03. Календарь**  
Как креатор, я хочу видеть все запланированные посты в удобном недельном календаре с цветовой разметкой по платформам и перетаскивать их пальцем.

**US-04. Редактирование**  
Как креатор, я хочу изменить описание, время, обложку или полностью отменить уже запланированный пост.

**US-05. Уведомления**  
Как креатор, я хочу получать push-уведомление об успешной публикации и об ошибке.

**US-06. История + аналитика**  
Как креатор, я хочу видеть историю всех публикаций и базовые метрики (просмотры, лайки, сохранения).

**US-07. Работа без телефона**  
Как креатор, я хочу, чтобы публикация происходила даже если мой iPhone выключен или у меня нет интернета.

**US-08. Управление аккаунтами**  
Как креатор, я хочу быстро понять, что токен истёк, и переподключить аккаунт в один клик.

## 5. Функциональные требования

### 5.1. Авторизация
- Apple Sign-In (основной способ)
- Дополнительно: email + пароль
- Безопасное хранение сессии

### 5.2. Подключение социальных сетей
- OAuth 2.0 для каждой платформы
- Экран «Аккаунты» со статусом (подключён / требует внимания)
- Кнопка «Переподключить»
- Автоматическая проверка валидности токенов

### 5.3. Загрузка и подготовка видео
- Выбор из Photos, Files или Camera
- Строгая валидация: соотношение 9:16, длительность ≤ 60 секунд
- Предпросмотр
- Возможность загрузить **отдельную обложку** для каждой платформы
- Сохранение в «Черновики»

### 5.4. Создание мульти-поста
- Список платформ с чекбоксами (можно выбрать любую комбинацию)
- Для каждой выбранной платформы — отдельное большое текстовое поле «Описание»
- Пользователь сам вставляет артикул (например #WW1233455)
- Кнопки «Скопировать описание» между полями
- Одно поле «Дата и время» (timezone по умолчанию — Europe/Moscow)
- Кнопки: «Сохранить черновик» / «Запланировать»

### 5.5. Календарь и управление расписанием
- Недельный календарь (понедельник — воскресенье)
- Цветовая кодировка:
  - Instagram — #E1306C
  - TikTok — #000000
  - YouTube — #FF0000
  - VK — #0077FF
  - Pinterest — #E60023
- Drag-and-drop перенос постов
- Список «Очередь»
- Редактирование и удаление постов до публикации

### 5.6. Автоматическая публикация (критически важно)
- Видео + метаданные загружаются в облако
- Задача ставится в надёжную очередь с точным временем
- В момент X сервер:
  1. Берёт видео
  2. Публикует параллельно во все выбранные платформы через официальные Content Publishing API
  3. При ошибке делает retry (до 3 попыток)
  4. Сохраняет результат (ID поста, ссылка, статус)
- Публикация **полностью независима** от состояния устройства пользователя

### 5.7. Уведомления
Только Push (APNs):
- Успешная публикация
- Ошибка публикации (с краткой причиной)
- Требуется переподключить аккаунт

### 5.8. История и аналитика
- Полная история публикаций
- Карточка поста:
  - Превью
  - Описания по платформам
  - Ссылки на опубликованные посты
  - Метрики: **просмотры, лайки, сохранения**
- Обновление метрик 2–4 раза в сутки

### 5.9. Хранение
- Видеофайлы: 7 дней после публикации → автоматическое удаление
- Метаданные и аналитика: бессрочно

## 6. Нефункциональные требования

- **Надёжность публикации:** ≥ 97%
- **Скорость:** от «Запланировать» до подтверждения ≤ 15 сек
- **Безопасность:** токены только в Keychain + server-side encryption, HTTPS only
- **UX:** максимально простой, iOS-native стиль, светлая + тёмная тема
- **Язык:** русский (основной)
- **Устройства:** iPhone 12+ и все iPad
- **Offline:** черновики и календарь доступны без интернета

## 8. Критерии приёмки MVP

1. Загрузка вертикального видео ≤ 60 сек работает.
2. Можно выбрать несколько платформ и заполнить разные описания.
3. Можно назначить время по Москве и запланировать.
4. Пост отображается в недельном календаре и его можно перетащить.
5. В заданное время видео **автоматически публикуется** (даже при выключенном iPhone).
6. Приходят корректные push-уведомления.
7. В истории есть рабочие ссылки на посты.
8. Подтягиваются просмотры, лайки и сохранения.
9. При истечении токена приходит уведомление и есть кнопка переподключения.
10. Приложение стабильно работает на iPhone и iPad.

## 9. Ограничения и риски

- Instagram требует Creator/Business аккаунт + привязку к Facebook Page.
- TikTok Content Posting API имеет лимиты и требования к аккаунту.
- Pinterest Video Pins имеют более сложный workflow (отложить на Этап 2).
- API платформ могут меняться — нужен абстрактный слой публикации.
- App Store Review: следовать Guidelines с первого дня.
